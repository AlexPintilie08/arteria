# SIM geography catalog and connected analysis

The `/app` workspace loads the SIM neighborhood catalog as a geographic reference layer. It serves `web/public/data/iasi-neighborhoods.geojson`, copied byte-for-byte from this repository's `sim/iasi-neighborhoods.geojson`, plus a validation index generated by SIM's `load_neighborhood_catalog` and `validate_neighborhood_boundary` loader functions.

The catalog is EPSG:4326 and contains a bounded, partial OpenStreetMap place query. It currently has 24 Polygon/MultiPolygon records and 7 named Point records. OSM place extents are not official or legal administrative boundaries. Point-only places remain points; the preview never infers their outlines. Each feature keeps its source object ID/URL, retrieval time, and uncertainty note. Attribution is `© OpenStreetMap contributors`; the catalog is distributed under ODbL-1.0. See the upstream `sim/NEIGHBORHOODS_LICENSE.md` for the full licensing notes.

The map preserves the five demo bookmarks separately. Eligible sourced polygons can be submitted by catalog ID to SIM v3 for pedestrian graph analysis; the backend loads the canonical geometry itself and fetches OpenStreetMap data only after the user starts that analysis. Point-only places and polygons outside SIM's standard limits are blocked before data acquisition. Signal-timing scenarios remain a separate synthetic demo, and graph analysis does not run SUMO.

## Refresh the local copy

From PowerShell in the repository root, run:

```powershell
.\frontend\scripts\refresh-sim-geography.ps1
```

By default the script reads this repository and uses its `.venv\Scripts\python.exe` when available. To use another SIM checkout or Python interpreter:

```powershell
.\frontend\scripts\refresh-sim-geography.ps1 -SimWorkspace 'F:\path\to\arteria' -PythonPath 'F:\path\to\python.exe'
```

The script copies the catalog into the frontend's public data folder and regenerates SIM's default validation results and SHA-256 record. It does not query Overpass; a new OSM snapshot must first be produced by the SIM catalog workflow. The API worker also reads the in-repository catalog directly.
